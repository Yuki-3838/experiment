# ゲーム速度・リザルト宝箱・カメラデバッグ

`GameDebugController.cs` 1本に、ゲーム速度、結果の宝箱開封待ち時間、キャラクターへのカメラフォーカス、Inspectorの操作ボタンをまとめています。旧名はGameSpeedDebugControllerです。ゲーム固有のアセンブリ参照やInspectorへのオブジェクト指定、追加パッケージは不要です。

## 設置

1. `GameDebugController.cs` を対象プロジェクトの `Assets/` 以下へコピーします。Editorフォルダには入れません。旧 `GameSpeedDebugController.cs` は新しいファイルへ置き換え、両方を残さないでください。
2. 旧版でシーンやPrefabにアタッチしたデバッグコンポーネントは外します。専用の空のGameObjectなら、そのGameObjectを削除します。
3. Playすると、起動時に `GameDebugController` が1つだけ自動生成されます。Hierarchyの `DontDestroyOnLoad > GameDebugController` を選ぶと、Inspectorに操作ボタンが表示されます。

自動生成はEditorのPlayとDevelopment Buildで有効です。スクリプトのアタッチやシーンの変更は不要です。初期設定をシーンで指定したい場合は、専用の空のルートGameObjectに手動でアタッチする従来の使い方も可能です。その場合、再読み込みするシーンへの配置は避け、起動用シーンに置きます。

旧版の `Editor/GameSpeedDebugControllerEditor.cs` は削除してください。Inspector用コードもこの1本に含まれています。旧 `BattleResultFastForwardController` がアタッチされている場合は外して、同じ待ち時間を二重に短縮しないようにします。

GameDebugControllerが複数作られた場合は最初の1個を保持し、後のコピーは動作を始める前に無効化して除去します。ゲームの管理オブジェクトへ取り付けられている場合は、デバッグコンポーネントだけを除去します。同じ本体が設定値を持ち続けます。

## 操作

- **Game Speed**: Pause、0.25x、0.5x、1x、2x、5x、10x。ゲームの `Time.timeScale` を変更します。
- **Follow Game Speed**: 初期状態でONです。結果の開封待ち・金額加算・ポップアップの時間もゲームの倍率に合わせます。
- **Result / Chests の倍率ボタン**: 結果だけ別の速度にします。押すとFollow Game SpeedがOFFになります。
- **Skip Result Waits**: 対応する結果の待ち時間を0にして、最終結果までの順次処理を早めます。結果の計算や表示完了処理は元のゲームが実行します。
- **Reset**: 開始時のゲーム速度、結果1x、待ち時間スキップOFFに戻します。FollowがONなら、結果速度は戻したゲーム速度に合わせます。

結果画面が非表示でも検出し、表示時に生成されるチームレーンも追跡します。InspectorのDetected results / timing fieldsで検出数を確認できます。コンポーネントを無効化・破棄すると、変更した時間設定と開始時のゲーム速度を復元します。

## 試合ループ・シーン再読み込み

Play中の設定はシーンを再読み込みしても引き継ぎます。保持するのはゲーム速度（Pauseを含む）、結果速度、Follow Game Speed、Skip Result Waits、Result Clock、チームのプルダウン選択、手動フォーカスの色と番号です。

デバッグ用GameObjectの生成処理はPlay開始時に1回だけ実行し、生成したオブジェクトを `DontDestroyOnLoad` に残します。MazeExploreには配置しないため、再読み込みで新しいデバッグ用オブジェクトは生成されません。同じオブジェクトが設定値を持ち続け、同じInspectorを使い続けられます。

カメラは古いキャラクターの参照を引き継がず、次の試合で生成される同じ色・番号のメンバーを探して追従します。生成待ちはInspectorにWaitingと表示します。Autoを押した場合は、次の試合も自動観戦になります。

コンポーネントを無効にしてもデバッグ用GameObjectは残ります。再有効化すると、そのオブジェクトが保持している設定を再適用します。手動配置では専用の空のルートGameObjectを使用してください。

保持する範囲は同じPlayセッションです。Playを停止して開始し直したときは、スクリプトの初期設定から始まります。手動配置の場合はシーンに保存した設定を使います。`Reset` の基準速度は、再読み込み後も最初の開始時の値です。

## カメラフォーカス

Play開始時は赤チームの1番をフォーカスします。まだ生成されていなければWaitingになり、生成後に自動で追従します。プルダウンの初期選択も赤です。

Inspectorの **Camera Focus** で **Team** のプルダウンから赤・青・黄・緑を選び、**1・2・3・4** のいずれかを押すと、そのチームに登録された順のキャラクターへ観戦カメラが移動して追従します。番号は画面上では1始まりで、ゲーム内部のメンバー番号0〜3に対応します。プルダウンの変更は、番号を押した時点でカメラへ反映します。

**Auto** で元の自動観戦へ戻します。同じ試合内で追従対象が破棄・非表示になった場合やデバッグコンポーネントを無効化した場合も、自動観戦へ戻します。シーン再読み込みでは同じ色・番号を次の試合で探します。Pause中でも番号ボタンでカメラを切り替えられます。未生成・非表示のキャラクターや無効な観戦カメラには切り替えません。

実際の表示色からチーム番号を照合し、Inspectorに番号と色見本を表示します。現在の配色は赤枠がオレンジです。

| プルダウン | 現在のチーム番号 |
| --- | --- |
| 赤（オレンジ） | Team 1 |
| 青 | Team 4 |
| 黄 | Team 3 |
| 緑 | Team 2 |

ゲームの `BattlePrototypeGameController.SpawnedParties` とパーティーの `TryGetMember` から実際の登録メンバーを解決し、既存の `BattleSpectatorCameraController` へフォーカスを指定します。自動観戦の選択で上書きされないよう手動フォーカスを保持し、チーム表示も合わせます。別の環境でも同じ1ファイルを差し替えて使用できます。

## 対象と時間の扱い

SuperDungeonWarsの `BattleResultPresentation` と `BattleResultTeamLane` を型名で探し、公開またはSerializeField付きfloatのうち、Duration・Delay・Intervalで終わる時間設定だけを調整します。スコア、順位、戦闘中の行動間隔、宝箱配置の物理設定は変更しません。ゲームのC#ファイルを変更する必要はありません。

**Result Clock = Automatic**はEditorで対象スクリプトを読み、実時間を使う元の版と、スケール時間へ変更済みの版を判別します。スケール時間版はTime.timeScaleを補正して、倍率が二重にならないようにします。独自に時間を混在させた版は、Result ClockでUnscaledまたはScaledを指定してください。プレイヤービルドではAutomaticは元の版に合わせてUnscaled扱いになります。Editor用コードはビルドから除外されます。

## 制限

- すでに生成された `WaitForSecondsRealtime` の残り時間は書き換えられません。倍率やスキップは結果開始前に指定すると、最初の待ちから反映されます。
- Pauseはスケール時間を止めます。実時間で動く結果コルーチンの完全停止には対応していません。
- 対象の型名や時間フィールドの規則が異なるゲーム、コードへ直接書かれた秒数、Animator内部の遷移時間はこの時間設定変更の対象外です。
- Skip Result Waitsも、宝箱配置の完了待ちやフレーム単位のyieldを強制終了する機能ではありません。
