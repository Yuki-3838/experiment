# リザルト待ち時間の短縮 — 汎用の単体スクリプト

**2026-10-26 単体版。** UnityとC#標準機能だけで構成したC#1本。ゲーム固有の型、特定ゲームの固定フィールド名、外部DLL、追加スクリプト、Inspectorの参照設定は不要。

[BattleResultFastForwardController.cs](BattleResultFastForwardController.cs) を、リザルト画面のルートGameObjectへアタッチする。SuperDungeonWarsの既定シーンなら、GameObject **BattleResultPresentation** が取り付け先の例になる。これは配置場所の例であり、そのクラスを参照する実装ではない。

## 導入

1. UnityのPlayを停止する。
2. C#1本を `Assets/LocalTools/ResultFastForward/` などへコピーする。既に同名スクリプトがある場合は、その内容を置き換える。既存のmetaを維持し、同じクラスのファイルを2本置かない。
3. 結果画面のルートGameObjectへ、このコンポーネントを1回アタッチする。既に付いていれば追加し直す必要はない。
4. `Fast Forward Multiplier` は初期値 **5** のままで使用できる。
5. Playを開始し、通常どおり結果画面の精算演出を開始する。

## 単体で行う処理

アタッチ先と、その子オブジェクトのMonoBehaviourを調べ、次の条件を満たす設定を短縮する。

- インスタンスのfloatフィールド。
- public、またはUnityのSerializeFieldが付いている。
- 名前が **Duration / Delay / Interval** のいずれかで終わる。大文字小文字は区別しない。
- readonlyやNonSerializedではなく、値が正の有限数。

これらは秒数として扱う。ゲーム固有のクラス名や変数名の一覧は持たず、Reflectionで一般的な命名の時間設定を列挙する。ローカルの配布ソースでは、開封前・次の開封まで・金宝箱の待ち・金額表示などの9項目がこの規則に当てはまる。

後から生成されたポップアップも自動で対象にする。対象のインスタンスは一度だけ設定し、毎フレーム割って小さくなり続けることはない。

## 秒数と復元

倍率が1より大きい場合、変更後の秒数は **min（元の秒数、0.35秒）÷倍率**。倍率5なら、元が2秒でも設定値は0.07秒になる。元が短ければ、その短い値を基準にする。これは時間設定の値で、フレーム境界を含む実測時間ではない。

倍率1なら短縮を適用しない。倍率を変える場合は、Play停止中に設定するか、コンポーネントを無効→有効にする。無効化時には、自分が設定した値のままの項目を元へ戻す。途中で手動変更された値は上書きしない。

`Time.timeScale` は変更しない。実時間待ちでも、その待ちが対象の設定値を使っていれば秒数の短縮が作用する。

## 対象の範囲

このスクリプトが短縮するのは、上記の命名規則に合う時間設定。**コードに直接書かれた待機、対象の接尾辞がない設定、プロパティ、float以外の値、別オブジェクト配下の処理は対象外。** 任意のゲームのすべての待機を強制的に短縮する実装ではない。

結果画面のルートへ取り付ける。アタッチ先配下の条件に合う時間設定が対象になるため、シーン全体や参加者AIをまとめたルートへ付ける用途には向かない。ゲーム固有の型やasmdef参照を追加する必要はない。
