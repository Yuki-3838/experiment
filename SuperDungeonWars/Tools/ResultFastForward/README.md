# リザルト宝箱の開封短縮 — アタッチするスクリプト1本

[BattleResultFastForwardController.cs](BattleResultFastForwardController.cs) を、配布プロジェクトの `BattleResultPresentation` が付いたGameObjectへアタッチして使用する。既定のシーンでは、GameObjectの名前も **BattleResultPresentation**。追加のInspector参照は不要。

## 導入

1. UnityのPlayを停止する。
2. このC#ファイルをプロジェクトの `Assets/Dungeon/Program/Game/Debug/` などへコピーする。同名スクリプトがあればその内容を置き換える。既存のmetaは維持し、同じクラス名のファイルを2本置かない。
3. Hierarchyの **BattleResultPresentation** を選び、このスクリプトを追加する。既に付いていれば追加し直す必要はない。
4. `Fast Forward Multiplier` は初期値 **5** のままで使用できる。
5. Playを開始し、通常どおり結果画面でEnterまたはSpaceを押して精算演出を開始する。

このフォルダーのスクリプト1本で、開封と金額表示の待ち時間を実行時に設定する。ほかのC#ファイルの差し替えや、シーン／Prefabの待ち時間の手作業による編集は不要。以前の `ResultFastForward.patch` を追加適用する必要もない。

## 処理

- 開始待ち、開封前、次の宝箱まで、金宝箱の開封前、合計金額のカウント、最後の表示待ちを短縮する。
- 結果画面の子に生成される各チームの金額ポップアップも自動で見つけ、出現・保持・消去を短縮する。
- 配布版の `WaitForSecondsRealtime` や `Time.unscaledDeltaTime` による表示にも、秒数の設定を短くすることで対応する。
- 各インスタンスに一度だけ適用する。コンポーネントを無効にすると、まだ自分の設定値のままの項目を元へ戻す。

`Time.timeScale` は変更しない。宝箱の開閉は配布版の開閉モデル切り替えを使用し、次の宝箱を開くまでの待ちを短くする。

## 調整値

倍率を適用する前の上限は次のとおり。

| 項目 | 秒数上限 |
|---|---:|
| 開始待ち | 0.20 |
| 合計金額カウント | 0.08 |
| 次の宝箱まで | 0.05 |
| 開封前 | 0.04 |
| 最後の結果表示 | 0.25 |
| 金宝箱の開封前 | 0.35 |
| 金額ポップアップの出現 | 0.06 |
| 金額ポップアップの保持 | 0.18 |
| 金額ポップアップの消去 | 0.08 |

倍率が1より大きい場合、設定秒数は **min（元の秒数、表の上限）÷倍率**。倍率5なら、例えば元の金宝箱待ちが2秒でも設定は0.07秒になる。元の設定が上限より短ければ、その値を基準にする。

倍率1なら短縮を適用しない。倍率の変更は、Playを停止して設定するか、このコンポーネントを無効→有効にして反映する。フレームの境界やほかの演出があるため、設定値は画面全体の実測時間ではない。

## 対応範囲と確認状況

対象は、この配布プロジェクトの `BattleResultPresentation` と `BattleResultTeamLane`。公開の時間設定APIがないため、結果表示のprivateなfloatフィールドを名前指定のReflectionで読み書きする。点数や宝箱結果は変更しない。

配布版の更新で対象のフィールド名が変わった場合は、Unity Consoleへ警告を出し、見つからない項目を飛ばす。この版はローカルの配布ソースとフィールド定義を照合したが、**Unity起動・コンパイル・再生確認は未実施**。実測による速度改善の確認はしていない。
